# Managing Work and Projects

> Classification: Canonical user guide
> Audience: Individual professionals, creators, and project owners
> Capability status: Current workspace; team collaboration is future
> Source authority: [Feature Catalog](../product/FEATURE_CATALOG.md) and [Plan and Focus](../product/PLAN_AND_FOCUS.md)
> Last verified: 2026-08-11

## Model work at useful levels

Use Work & Career as a continuing area. Give each finite outcome a project; use nested projects only when a child has its own outcome. Sections describe workflow or subject grouping. Tags should answer cross-cutting retrieval questions such as `deep-work`, `waiting`, or `client`, not repeat the hierarchy.

Write tasks as visible actions. Add notes only when they reduce ambiguity. Estimate duration and energy when those fields improve planning; use context and readiness to distinguish actionable work. Link subtasks and dependencies when sequence matters, but avoid decomposing routine work past usefulness.

## Run a project

1. Create the project in the correct life area or from a template.
2. Define the outcome in its description and add sections if the list needs shape.
3. Capture actions into Inbox, then assign project/section/tags during triage.
4. Use list view for sequence and detail; board view for stage movement. Moving a card changes the same project record, not a duplicate.
5. Place only ready work into Day/Week. Leave blocked or lower-readiness work in Backlog/Anytime.
6. Start scoped Focus from a task when you want the session history connected to work.
7. Review the project weekly. Complete, revise, or archive it when the outcome changes.

Moving a project between life areas preserves project/task identity. Archiving removes it from active choices while retaining history. Deletion is destructive: read how children, tasks, links, and evidence will be treated, and use Undo if offered.

## Meetings and waiting-for work

Calendar meetings are fixed context. Create preparation/follow-up tasks or an internal time block; do not expect LifeBoard to edit the external event. Notes can hold meeting reference material, and tasks can use a waiting tag/context, but a dedicated decisions/delegation/team workflow is not currently shipped. That direction is described only in the [future blueprint](../product/LIFEOS_FUTURE_BLUEPRINT.md).

## Protect work/personal boundaries

- Keep personal areas out of work-focused Home mode and projections.
- Attach only necessary context to EVA requests; review any proposal before Apply.
- Do not place Journal/health evidence into work notes merely for convenience.
- Use reminder quiet hours and separate calendar selection to prevent work from occupying Rest.

## Weekly controls

Use the This Week workspace to see Overdue, Inbox, and Anytime work alongside meetings and capacity. Filter by project/readiness/context/duration/energy, distribute a selected batch, inspect the receipt, and Undo a poor allocation. When overloaded, cut scope before extending every day.

## Current limits

LifeBoard currently manages personal canonical projects. Milestones, decision records, structured meeting notes, delegation, shared projects, team permissions, and workload forecasting are future requirements, not hidden current features.
