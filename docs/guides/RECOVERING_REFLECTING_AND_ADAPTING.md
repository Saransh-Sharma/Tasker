# Recovering, Reflecting, and Adapting

> Classification: Canonical user guide
> Audience: Users whose plans changed, accumulated, or became unhelpful
> Capability status: Current workspace
> Source authority: Daily Loop, [Plan and Focus](../product/PLAN_AND_FOCUS.md), [Journal and Reflection](../product/JOURNAL_NOTES_AND_REFLECTION.md)
> Last verified: 2026-08-13

Recovery is a normal stage of LifeBoard’s operating loop. The goal is an honest next plan, not preserving an obsolete one.

## Repair an overloaded day

1. Open Home or Plan → Day and read capacity/fixed commitments.
2. Preserve essential care and one or two meaningful outcomes.
3. Use Replan or Minimum Viable Day.
4. Shorten, unschedule, or move flexible work; do not edit external calendar events as though they were LifeBoard tasks.
5. Inspect the planning receipt. Undo if the new arrangement is worse.

## Rescue overdue work

Open Overdue Rescue or the This Week overdue entry. For each task choose complete, clarify, reschedule, return to Anytime, delegate outside LifeBoard if appropriate, or delete. Process by intent—not only oldest date. If a batch partially applies, use its receipt and retry only unapplied items.

## Recover a Focus session

If the app closes or the device changes state, reopen Focus. Startup repair reconciles the active session, notifications, and Live Activity. Resume, finish with an outcome, or abandon with confirmation. An interruption can be recorded without declaring the session failed. Rewards/history must occur once.

## Correct tracking evidence

Open the habit, tracker, care, meal, fasting, or goal history and edit/delete the original record when allowed. Correct the source rather than adding an opposite record. Imported Health samples may need correction in their owning app. Explicit zero remains valid; “no data” is different.

## Journal and reflect

Journal can include text, dictation, saved audio/transcription, scans, photos, and files. Review before save. Original audio remains authoritative if transcription fails. Locking protects routes and app-switcher previews; search and semantic indexing inherit the same sensitivity.

In Weekly Reflection:

- start with observed facts and evidence links;
- note wins, friction, capacity, habits/goals, health signals, and unfinished work;
- label interpretation separately;
- treat sparse evidence as insufficient;
- decide one structural change for the next week.

Use Insights as prompts, not verdicts. Trends are non-causal and health language is non-clinical.

## Use EVA safely

Attach only relevant categories and ask EVA to explain its evidence. For a proposed schedule/task/habit change, inspect the diff, then Apply, Edit, or Not Now. If application is partial, read exactly what changed. Use receipts and Undo. Stop streaming, Continue, or Retry when generation state is unclear; model failure never grants permission to bypass review.

## Adapt the system

- Pause or archive habits/routines that no longer fit.
- Change working hours, week start, timeline anchors, reminders, or quiet hours.
- Move projects between life areas and archive completed outcomes.
- Remove Home cards that create noise.
- Clear or constrain EVA memory/context.
- Revisit permissions and connected data.

If bootstrap, migration, model, indexing, sync, or projection state appears damaged, use Settings → Recovery and preserve diagnostics without including private content.
